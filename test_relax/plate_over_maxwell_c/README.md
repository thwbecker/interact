# Plate_over_Maxwell C port

C translation of Kaj M. Johnson's (Indiana University) MATLAB codes for
postseismic surface deformation due to uniform slip on a rectangular
dislocation in an elastic plate over Maxwell viscoelastic layer(s),
using a semi-analytical propagator matrix solution:

- `Plate_over_Maxwell.m`: elastic plate over Maxwell halfspace, patch
  represented by a single point source, closed-form (cubic) Laplace
  inversion, multiple output times.
- `Plate_over_Maxwell_Layer_over_Halfspace_Displacements.m` and
  `..._Velocities.m`: elastic plate over a Maxwell viscoelastic layer
  over a Maxwell viscoelastic halfspace, Gauss-Legendre quadrature of
  point sources over the patch, degree-7 denominator polynomial in the
  Laplace domain, single output time.

The port aims to be a faithful translation, including the original
parameter conventions, wavenumber sampling, quadrature defaults, and
sign conventions of each code. Units: km, years, m, m/yr.

## Files

- `pom.h`, `pom_util.c`, `pom_layer.c`, `pom_maxwell.c`: library
- `terms_2visc.c`: polynomial coefficient functions, machine translated
  from the (Mathematica generated) expressions in the Displacements
  m-file by `gen_terms.py`; regenerated by `make terms_2visc.c`
- `pom_main.c`: command line driver, writes `x y ue un uz` tables
- `Makefile`: plain assignments, no environment variable indirection
- `run_verification.sh`, `gen_reference.m`, `roots.m`: verification
  against the original codes run under Octave (see below)
- `run_example.sh`: reproduces `run_postseismic_example.m` with GMT
- `make_movie.sh`: computes time series of deformation fields and
  renders an mp4/gif movie with GMT and ffmpeg

## Build and use

    make
    ./pom layer   [options]     # plate / viscoelastic layer / halfspace
    ./pom maxwell [options]     # plate / Maxwell halfspace, point source

Run `./pom` without arguments for the option list. Defaults reproduce
the configuration of `run_postseismic_example.m`. Example:

    ./pom layer -m 200 20 20 90 0 0 0 1 0 0 -t 10 -tR1 25 -tR2 25 \
        -grid -300 300 61 -300 300 61 -o disp_t10.txt

Output tables are plain text and can be fed to GMT directly; see the
two shell scripts for worked examples (vector plots, grdimage of the
vertical component, frame loop assembled with ffmpeg).

## Verification

`run_verification.sh` runs the original m-files under Octave at ten
test stations and compares them with the C port. Octave's `roots()`
orders roots at zero differently from MATLAB, which breaks the
original codes under Octave; the local `roots.m` wrapper restores
MATLAB's ordering for this purpose. Results for the tested
configurations (scaled maximum differences over east, north, up):

    layer disp strike-slip        ~1e-9
    layer vel strike-slip         ~1e-8
    layer disp dip-slip 30        ~8e-8
    layer disp tensile oblique    ~3e-7
    layer disp mixed, tR1=tR2     ~5e-5   (see conditioning note below)
    maxwell disp t=1,5,10         ~1e-12

One deviation from a line-by-line translation: the port evaluates the
Bessel functions once per station and source rather than once per
mechanism and Fourier order, which reduced runtime by roughly a
factor of three in our grid tests without changing the computed
values (verification figures above are with this change).

The maxwell code uses the same closed-form cubic in both versions and
agrees essentially to machine precision. The layer code finds the
seven nonzero denominator roots iteratively (Aberth method) rather
than through the companion matrix eigenvalues used by MATLAB, which
appears to account for the residual differences at the 1e-7 to 1e-9
level in the cases tested. These figures are specific to the test
stations and parameters in `gen_reference.m` and should not be read as
general error bounds.

## Numerical notes and caveats

- Equal relaxation times: for tR1 = tR2 the denominator roots become
  nearly repeated and the partial-fraction inversion is ill
  conditioned. In a test with the original code under Octave, a 1e-9
  relative perturbation of tR2 changed the output by about 3e-5
  relative, so agreement between any two implementations can probably
  not be expected beyond that level in this regime. Note that the
  example script distributed with the original codes uses tR1 = tR2.
- Near-fault artifacts: within a few tens of km of the fault trace
  the vertical component shows a checkerboard-like oscillation whose
  period equals the along-strike spacing of the quadrature point
  sources (20 km for the default NL = ceil(0.05 L) with L = 200 km,
  combined with a single source line at mid-fault depth for NW = 1).
  It is a property of the source discretization, present in the
  original as well (the port reproduces the original's near-fault
  values within the precision of that comparison). Refining the
  quadrature, for example `-nl 40 -nw 8` for the example fault,
  removed the oscillation in our tests and appeared converged (about
  6e-4 relative against a further refinement); cost grows linearly
  with nl times nw, about a factor 32 over the defaults here.
  `run_example.sh` and `make_movie.sh` therefore pass `-nl 40 -nw 8`
  by default (set nl and nw to 0 at the top of the scripts for the
  original behavior); `-nl 30 -nw 4` agreed with that setting to
  about 6e-4 relative in a near-fault test at roughly two thirds of
  the cost, if runtime matters. The plain `pom` command keeps the
  original defaults unless `-nl`/`-nw` are given.
- Wavenumber truncation: with the refined source quadrature, results
  at 5 km and more from the trace changed by only about 0.5 percent
  between kmax = 0.5 and 0.7, so kmax = 0.5 appears adequate there
  and is not the cause of the near-fault oscillation. Raising kmax
  much further is not possible in this formulation: the propagator
  matrices grow like exp(k H2), and in our tests double precision
  cancellation failed beyond roughly k H2 = 32 (kmax near 0.8 for
  H2 = 40), with clearly unphysical output by kmax = 1. The
  original's kmax = 0.5 sits sensibly below that ceiling. The
  wavenumber spacing (0.005/km) also gives only a few samples per
  Bessel oscillation at station distances beyond roughly 200 km;
  the port reproduces the original's choice, and agreement with the
  original does not by itself establish far-field quadrature
  accuracy.
- Stations at r = 0 above a point source produce NaN in the original
  through 0/0 in the Bessel recurrences; the port guards these with
  small-argument series. Away from such points this changes nothing.
- Quadrature defaults: the original Displacements code uses
  NL = ceil(0.05 L) point sources along strike, the Velocities code
  NL = ceil(0.025 L); it is not clear to me whether this difference is
  intentional. The port reproduces each default and exposes `-nl`,
  `-nw` overrides.
- Sign conventions: the layer codes document m(8) > 0 as left-lateral
  and behave accordingly in the configuration tested. For the same
  input, `Plate_over_Maxwell.m` (which negates m(8) internally)
  produced horizontal fields of the opposite sign in a degenerate-layer
  comparison (tR1 = tR2, same elastic plate), i.e. its positive
  strike-slip appears right-lateral relative to the layer codes. The
  port preserves each original's behavior; users combining the two
  codes may want to check the convention for their use case.
- The maxwell code represents the whole patch by one point source and
  is documented as accurate only for patches small compared to the
  plate thickness; magnitude differences relative to the layer code in
  the degenerate comparison above are consistent with that limitation
  for the large example patch, though I did not isolate the separate
  contribution of the gravity correction term (present in the layer
  code, absent in the maxwell code).

## Movies

`make_movie.sh` computes the field on a 61 x 61 grid for a sequence of
times (a few seconds per frame in the test environment used here), plots each
frame with GMT (vertical component as a color field with a fixed,
symmetric color range across frames; decimated horizontal vectors;
fault trace), and assembles mp4 and gif output with ffmpeg. All
parameters (fault, rheology, grid, times, scales) are plain
assignments at the top of the script.

## Conventions and checks added 2026-10-05

Relaxation time.  `tR`, `tR1`, `tR2` are relaxation times in Johnson's
convention, tR = 2 eta / mu, i.e. TWICE the Maxwell time eta / mu (the
m-file header of the layer code says so: "Maxwell relaxation time
(2*eta/mu, ...)"; this is the Savage and Prescott 1978 tau_a).  The
rest of interact uses eta / mu: rsf_solve `-ve_tmaxwell_yr`, the
inplane_ve_proto `tau`, and the Miyake-Noda, Kato and Rundle anchors
state the factor 2 explicitly.  To run this code at a Maxwell time
t_M, pass tR = 2 t_M.  The help text now says so.

Exact test of the time dependence (`run_sp_test.sh`).  An infinitely
long vertical strike-slip fault cutting the whole plate over a Maxwell
half-space of the same rigidity has the closed-form postseismic
solution of Savage and Prescott (1978), an image series with time
factors 1 - e^{-t/tau_a} sum_{m<n} (t/tau_a)^m/m!.  With tR read as
tau_a the layer code matches it (x = 12 to 100 km, H = 30 km); with
tR read as the Maxwell time it is 50 percent off at t = 2 tR.  The
original wavenumber sampling (NK = 100, uniform to 0.5/km) is 1 to 3
percent low at t = 2 tR and 7 to 12 percent low at t = 50 tR, because
late relaxation lives at long wavelengths the grid barely samples;
with 1000 samples the deficit is 0.2 to 0.8 percent at 2 tR and 2 to
4 percent at 50 tR.  Hence the new options `-nk n` (wavenumber
samples, default 100 as in the m-files) and `-rg v` (buoyancy term at
the plate base, default 3e-3 as in the m-files, 0 switches it off).
With the defaults the output is byte-identical to the previous
version.

Open item, dip-slip on a dipping plane.  In the 2-D limit (L = 1000
km, mid-strike) the postseismic change of a 30-deg surface-breaking
thrust (W = 30 km, bottom edge 15 km, plate 30 km, no buoyancy) does
not match the two independent 2-D codes in the repository
(test_relax/inplane_ve_proto/inplane2d.py and ve_thrust_relax.py, which
agree with each other to 1e-3 slip and with Rundle 1982 at 5 tau_a):
the basin is centred near the trace instead of 0.75 H down-dip.  It
does match the 2-D solution computed with the moment tensor of the
mirrored plane (dipping the other way) while the point sources stay on
the +dip-direction line, to 0.1 to 0.3 x 1e-2 slip in both components.
A vertical dip-slip fault gives an exactly antisymmetric field and the
strike-slip test above passes, so station and trace conventions are
not the cause.  The port reproduces the m-files to 1e-7, so this is in
the original or in a convention not yet understood; `pom_momtensor`
and the source rotation look mutually consistent on reading.  Until
resolved, results for dipping faults should not be used as a
reference.  Record of the comparison: ve_relax/pom_check/NOTES_pom_check.md
in the working folder of 2026-10-05.
